# Prose Voice

Write natural-language output so it reads as a person wrote it, not a model. The tell of machine writing is not any one punctuation mark. It is deploying marks in a mechanical, repetitive way a careful writer never would.

- Use every mark, the em dash included, the way a skilled writer does. Correctly, and only when it is the right mark for that sentence.
- The fault is the pattern, not the character. A stock cadence gives the machine away, such as an em-dash aside in sentence after sentence, or the same "not X, but Y" scaffold on repeat. Vary how sentences are built and let most run short.
- This governs prose only. Code, identifiers, config, and technical syntax keep the punctuation their language requires.
- Scope is every reply, not only files being written or a specific skill's drafts. A chat message is prose too, and drifts into the same mechanical cadence just as easily when attention is on the task instead of the sentence.
- Before sending anything longer than a couple of sentences, reread it once for this one failure: the same mark landing in the same role across consecutive sentences. Rewrite the offending sentences with a different construction; do not just swap in a different mark used the same mechanical way.
