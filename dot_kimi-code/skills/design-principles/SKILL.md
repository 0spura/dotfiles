# Design Principles

Use these principles when designing or reviewing user-facing interfaces. They are empirical guidelines, not aesthetic preferences.

## Clarity over density

Show the user what matters for the current task. Hide or defer secondary information. Every element earns its place by reducing uncertainty or enabling the next action.

## Match the mental model

Name things with the user's vocabulary, not the system's internals. Navigation and grouping should match how the user thinks about the domain.

## Progressive disclosure

Reveal detail on demand. Start with the simplest correct view and let the user drill in. Avoid settings-heavy surfaces for routine tasks.

## Feedback loops

Every action produces observable feedback. Loading, success, failure, and partial states are all designed, not leftover.

## Error recovery

Errors state what happened, why it matters, and the exact next step to recover. Never blame the user.

## Accessibility

Color is not the only signal. Interactive elements are reachable and operable. Text has sufficient contrast. Motion is reduced when the user requests it.
