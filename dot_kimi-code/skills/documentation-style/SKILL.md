# Documentation Style

Apply this style to all written documentation: SRS, architecture, ADRs, code comments, and project docs. Chat replies may use lighter language.

## Simplified Technical English (ASD-STE100)

Use one word per meaning. One verb per action. No synonyms. No subordinate clauses. No embellishment.

- Pick one term per concept and reuse it. Do not vary vocabulary for the same thing across a document for the sake of variety.
- One clause per sentence. If a sentence needs "and," "which," or a comma aside to carry a second idea, split it into two sentences.
- State the action or the fact directly. Cut hedges, throat-clearing, and filler such as "in order to," "it is worth noting that," or "essentially."
- Active voice, direct address. Say who does what to what. Avoid the passive unless the actor is genuinely unknown.

## Relaxation for explanations

ASD-STE100 is mandatory for instructions, procedures, and requirements. For explanations, justifications, and context, use natural simple language. The goal is clarity, not purity.

## Structure

- One idea per paragraph.
- Use headings to separate concerns. Do not nest deeper than three levels in ordinary docs.
- Use lists for sets of items or steps. Use prose for narrative.
