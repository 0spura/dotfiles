Use the design-principles skill. Use accepted requirements and observed user context as
the source of truth. Define the primary flow and only its material states,
feedback, recovery, accessibility, responsive behavior, and success evidence.
Resolve ambiguity instead of inventing product behavior. Reference requirements
rather than repeating them. Save design artifacts only after approval; do not
decide backend or data architecture.
